# Нейро-Сёма — структура приложения и контекст

Документ для сохранения контекста по экранам, полям и правилам данных.  
Источник фактов по компаниям: Excel «обезличенные и маскированные данные по компаниям.xlsx».

---

## Маршруты

| Путь | Экран |
|------|--------|
| `/` | Стартовая (лэндинг + поиск) |
| `/search` | Редирект/наследие — поиск на главной |
| `/company/:companyId` | Карточка компании |

Параметры URL (поиск и карточка): `mode` (inn \| name \| group), `q`, `systems`, `page`, `section` (full-report \| offers \| risks).

---

## Стартовая страница (`/`)

- Брендинг «Нейро-Сёма», подзаголовок про подготовку звонка.
- **Поиск**: вкладки ИНН / Наименование / Группа, поле ввода, кнопка «Найти».
- **Фильтры систем**: SFA, Pega, ClaimCRM, AlfaClever, расчётный/кредитный конвейер, LM, ЕСКО, дашборд VOC.
- После поиска — результаты **под** строкой поиска (не отдельная страница):
  - Список компаний с пагинацией (**4** на страницу).
  - Кнопка свернуть/развернуть результаты.
  - Справа (на широком экране) — краткий summary выбранной компании.
- Анимация: сдвиг hero вверх, плавное появление результатов (`search-reveal`).

## Карточка компании (`/company/:id`)

### Шапка
- Название, summary, ИНН, контакт, группа, триггер (`lastEvent`), запрос (если был).
- Кнопка «Назад» — восстанавливает поиск и **номер страницы** (`page` в URL + `state.backPage`).

### Вкладки отчёта
1. **Полный отчёт**
2. **Предложения**
3. **Риски**

Кнопки на карточке в списке: «Полный отчёт» / «Предложения» / «Риски» — открывают ту же карточку с нужной вкладкой.

## Вкладка «Полный отчёт»

Блок **ReportGrid** (поля из Excel + выделенные поля модели):

| Поле UI | Источник |
|---------|----------|
| Наименование / ИНН | `name`, `inn` |
| Юридический адрес | нет в Excel → «Нет информации» |
| Сайт | `website` (только основной сайт из строки Excel «Сайт компании…») |
| ОКВЭД / записка | `okved`, `summary` |
| Финансовая отчётность | `financialStatements` |
| Выручка | `revenue` |
| ЧИ, ЧП | нет в Excel → «Нет информации» |
| Среднесписочная численность | `staffCount` |
| Контакты ЮЛ и ЛПР | `contactRole` |
| Сводка по достижениям | `lastEvent` |
| База эмиссии ТЭ и ИЭ | `offerChecks` (метка «База эмиссии ТЭ и ИЭ») |
| База ФТС. Участник ВЭД | `offerChecks` (метка «База ФТС. Участник ВЭД») |

Дополнительные блоки **FullReportBlocks** (данные из Excel):

| Блок UI | Поле модели | Строка Excel |

Лизинг (строка Excel 13) — только во вкладке **«Предложения»** (`offerChecks`).

Блок **«Соцсети, сайты, проф. статьи и достижения ЮЛ и его ЛПР»** (`publicPresence`):

| Поле | Содержимое |
|------|------------|

## Вкладка «Предложения»

Чек-лист `offerChecks` — **фиксированный порядок полей**:

1. Наличие оферты СББ  
2. Наличие оферты УТК  
3. Факторинг  
4. Льготные программы финансирования  
5. ЭБГ  
6. Участник аукционов по 223 и 44 ФЗ  
7. База эмиссии ТЭ и ИЭ  
8. База ФТС. Участник ВЭД

Соответствие строкам Excel (где есть): СББ → row 7, УТК → row 6, ФТС → 8, ТЭ/ИЭ → 9, 223 → 10, лизинг → 13.

Отображение: карточки с подписью сверху и значением снизу (`ChecklistPanel`).

## Правила данных (важно)

1. **Без синтетики** — не генерировать сайты, финансы, адреса. Только Excel + явные поля модели.
2. **Пусто / нет данных** — вручную ставить **«Нет информации»** (в т.ч. «нет инфо», «нет информации», пустая ячейка, прочерк).
3. **«нет»** из таблицы — оставлять как **«нет»** (факт из источника).
4. **«запрос на БП»** — не заменять на «Нет информации» (факт из Excel, строки ТЭ/ИЭ и ФТС).
5. **Публикации** — только во вкладке «Полный отчёт» / `publicPresence`, не в «Предложения».
6. **objectionHandling** — отдельно от предложений; не подмешивать в чек-листы.
